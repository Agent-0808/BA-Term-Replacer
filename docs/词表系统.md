# 词表系统说明

词表是本工具的译名替换层：在 OpenCC 繁简转换**之前**，把数据库文本里的繁体原文替换为社区/个人译名。手写词表与数据源条目在编译期合并为产物 `glossary/compiled.tsv`，patch 端只读这份产物，不再有任何合并逻辑。

- 键一律写数据库里的**繁体原文**，写错即零命中。
- 译文按流程写简体（t2s）或繁体（t2t）。
- `compiled.tsv` 四列：旧词/新词/mode/source。

## 目录结构与加载优先级

- `glossary/shared/*.tsv` —— 客观共识词表（角色名、地名、术语），入库共享，可 PR；个人偏好不要放这里。
- `glossary/local/*.tsv` —— 个人偏好词表，不入库；缺文件时自动从 `templates/` 复制。
  - 已存在的内容不覆盖，删除后重跑即得新模板。
- `glossary/templates/` —— 模板模板（name.tsv / text.tsv / blacklist.txt）。
- `glossary/compiled.tsv` —— 编译产物，gitignore，patch 的唯一输入，勿手编。

加载规则：

- 顺序为 **auto 条目（数据源）→ shared/\*.tsv → local/\*.tsv**，后加载者优先，直觉对应「自动 < 共享 < 个人」。
- 同键跨文件覆盖时打印报告；同一文件内重复键则**先出现者优先**。
- 文件名不承载语义，仅按字母序扫描一层目录；匹配方式全部由文件内的 mode 声明决定。

## 文件语法

手写词表一律两列 TSV：`旧词<TAB>新词`。

- 分隔符是 Tab **不是空格**，格式错的行会打印 `[glossary] 文件:行号` 告警并跳过。
- 编码 UTF-8，允许 BOM（兼容 Excel 导出）。
- `#` 开头的行是注释；空行与其余注释行跳过，可以用来分栏，分栏标题建议 `#----- 标题 -----` 风格。
- **`# mode: exact|sub|re`** **是行级游标声明**：从下一行起切换后续条目的归属。
  - 文件头的声明是第一段的缺省值（无声明则为 `sub`）。
  - 文件中间可随时再声明，**同一文件可分块混用多种 mode**。
  - 声明了未知 mode 会告警并保持当前游标。
- 恒等行（旧词 == 新词）视为模板里「待填」的占位，加载时自动跳过，不产生任何替换。
- 同一 mode 内重复键先出现者优先；同名键允许跨表（exact 与 sub 各司其职）。

示例（一个文件分块混用三种 mode，覆盖常见写法）：

```tsv
# mode: exact
#----- 角色名：整字段匹配 -----
都子	宫子
彌香	未花
#----- exact 模式必须完整匹配，因此歧义短词也安全 -----
旬	瞬
希望	望
#----- 全名修正：带特殊符号、常被机器译错 -----
白子＊TERROR	白子＊恐怖
#----- 纯 ASCII 拉丁名（ASCII 字段只走 exact） -----
Kei 凯伊
Soph    索芙

# mode: sub
#----- 正文术语：子串匹配，最长键优先 -----
奇普托斯	基沃托斯
高地人	海蘭德
蓋瑪特利亞	數秘術
#----- 皮肤括号键：只命中「角色名(皮肤)」复合串，不误伤正文里的裸词 -----
(單車)	(骑行服)
#----- sub 模式会替换长文本里的内容子串，不要加入存在歧义的角色名 -----
都子	宫子
彌香	未花

# mode: re
#----- 正文规则：Python re 语法 -----
#----- 上下文修正：否定前瞻——后面接「變/陷」等动词时不替换 -----
學生會(?!變|陷|在|要|被)	学生组织
#----- 编号系列词：捕获组反向引用 \1 -----
梅花園學生([A-H])	幼儿园学生\1
#----- 替换并重组：保留原文片段 -----
第([一二三])篇	第\1章
#----- 把总力战奖杯改成手办（捕获组重排，\2 在前、\1 在后） -----
# "氣墊船(野戰)白金獎盃" -> "若藻的白金手办(野戰)"
氣墊船\(([^)]*)\)([銅銀金白]+)獎盃	若藻的\2手办(\1)
# "氣墊船(野戰)的榮譽白金獎盃" -> "若藻的1:1白金手办(野戰)，可以放在咖啡厅展示"
氣墊船\(([^)]*)\)的榮譽([銅銀金白]+)獎盃	若藻的1:1\2手办(\1)，可以放在咖啡厅展示
```

## 三种模式

- **exact（整字段匹配）**：字段全文与旧词相等才替换。
  - 只命中角色名这类独立字段，旬/希望/光 这类与普通词同形的歧义短词也安全。
  - 纯 ASCII 字段（角色名的拉丁写法，如 `Kei`）**只走 exact**，不做 sub 也不经 OpenCC，避免误伤资源路径与内部标识符。
- **sub（子串替换）**：字段文本包含旧词即替换。
  - 单趟扫描、**最长键优先**（先长后短），替换结果不再参与后续匹配，避免 A→B 的结果再被 B→C 命中。
  - 因此「特殊长词优先、通用短词兜底」的写法是有效的。
- **re（正则规则）**：Python `re` 语法，捕获组可用 `\1` 反向引用。
  - 在 sub 之后逐条应用（普通词表优先，re 兜底做上下文修正），规则序即文件序。
  - 适合带上下文条件的改写（如否定前瞻）与「替换并追加」类规则。
  - 写法要点：
    - pattern 里的字面括号要写 `\(...\)`（裸 `(...)` 是捕获组），替换串里的括号不用转义。
    - 「任意内容」用 `[^)]*` 止于第一个右括号，别用贪婪的 `.*`；反向引用后紧跟数字时写 `\g<1>`。
    - TSV 按 Tab 分列，pattern 与替换串里不能出现 Tab。
  - 非法正则在编译期校验剔除，不进产物；素材与验证可用 `scan` 命令，见下文。

对含 CJK 的字段，完整应用顺序为 **exact → sub → re → OpenCC**。

## 编译流程

```
uv run batr glossary [--profile t2s|t2t] [--template] [--refresh]
```

1. **auto 条目**（仅 t2s profile 编入）：从 KivoWiki 民译数据自动生成（经 BA-characters-internal-id 分发的 students.json / skin\_map.json，缓存于 `work/`）。
   - 名段与全名连写同时编入 exact 与 sub 两张表。
   - 皮肤名编 exact 兜底；正文 sub 用带括号的键（如 `(單車) -> (骑行服)`），只命中「角色名(皮肤)」复合串。
   - OpenCC 转换后已相等的键跳过，不写入产物。
2. **手写词表**：扫描 shared/ 与 local/ 全部 .tsv，按 mode 游标归入三张桶；re 块先做编译期校验。
3. **黑名单过滤**：对一切来源（自动 + 手写）在编译末尾统一剔除。
4. **写产物** `compiled.tsv`：文件头记录 profile、生成时间与来源统计。

参数说明：

- `--profile t2s` 繁→简（编入 auto）；`--profile t2t` 繁→繁（只编手写，用于民译套壳流程）。
- `--template` 不编译，改为往 `local/name.tsv` 追加名段/全名/皮肤名恒等行模板、往 `local/text.tsv` 追加皮肤括号恒等行。
  - 已有内容逐行保留、只补新增键；本 mode 下已不在生成集合里的未填恒等行会被清理。
  - 繁→繁典型顺序：先 `--template` 生成模板并填写右列，再 `--profile t2t` 编译。
- `--refresh` 强制重新下载数据源。

## 黑名单

黑名单在编译期对**一切来源**过滤条目：`shared/blacklist.txt`（客观项，入库）与 `local/blacklist.txt`（个人项）合并使用。

- 格式为一行一个繁体键，可选第二列限定匹配方式（`exact` / `sub` / `re`），不写则三种都禁用。
- 写了未知范围按全部禁用处理并告警。
- re 规则的键就是它的 pattern 字符串，须与词表里写的完全一致。

想禁用某个自动生成的条目要**写黑名单，不要靠删行**——auto 条目不落盘，每次编译都从数据源重新生成。另有一个派生门控：名段被 exact 黑名单禁用时，由它派生的全名连写一并禁用（避免「黑名单 三森」后仍替换出「水羽三森」）。

```tsv
# 个人黑名单示例
三森          # 三个匹配方式全部禁用
希望	sub     # 整字段匹配（角色名表）照常，仅禁用正文子串替换
未來	sub
```

## scan：为 re 规则收集素材并验证

写 re 规则前先用 `scan` 命令观察词语在文本里的真实形态，再据此设计正则，写完后再用 `scan --regex` 验证会命中哪些句子：

```
uv run batr scan <关键词...> [--db <db>] [--regex] [--tables 正则] [--limit N]
uv run batr scan <关键词...> --diff <另一个db>   # 两库命中数对比（验证替换效果）
```

注意 `--db` 的选择：

- 省略时 scan 会自动定位游戏客户端内的库，但**游戏目录里的库可能已被改动过**（打过补丁）。
- 分析词表应以未改动的原始库为准：用 `uv run batr backup` 复制出干净副本，示例统一用 `--db work/db/ExcelDB.db`。

典型流程（以「学生会长」类复合词为例）：

1. **字面扫描看上下文**：`uv run batr scan 學生會 --db work/db/ExcelDB.db`，输出该词出现在哪些表、每表样本（截取前 100 字符）。
   - 观察样本发现：`學生會的活動`、`學生會長` 这类该替换，`學生會變強了` 这类不该替换。
2. **设计正则**：否定前瞻排除动词上下文，得到 `學生會(?!變|陷|在|要|被)`。
3. **用 --regex 验证**：`uv run batr scan "學生會(?!變|陷|在|要|被)" --regex --db work/db/ExcelDB.db`，确认命中样本里没有不该动的句子。
   - scan 默认按字面量解释关键词，元字符需 `--regex` 才按正则解释，且无需转义。
4. **编号类复合词同理**：扫描发现 `偵查部學生A` \~ `偵查部學生H` 的系列写法后，写 `偵查部學生([A-H]) -> 侦查部学生\1`。
   - 用 `scan "偵查部學生[A-H]" --regex` 确认覆盖全集。
5. **替换效果对比**：patch 生成输出库后，用 `uv run batr scan 學生會 --db work/db/ExcelDB.db --diff output/ExcelDB.db` 对比两库命中数，替换生效则输出库命中应显著下降。

## patch 端应用与排查

patch 阶段从 `compiled.tsv` 加载词表（合并逻辑已在编译期完成），对每条文本按 `exact → sub → re` 应用并累计命中数。

- 结束时输出**逐规则命中日志**（TSV，含旧词/新词/mode/source/hits，hits 降序、零命中沉底）。
- `--dry-run` 只扫描统计不写文件，命中日志照常输出。
- `hits=0` 是拼错或过期词条的主要排查线索：
  - 键写错、写了简体而不是繁体、mode 用错都会导致零命中。

## 端到端示例

编译后 `compiled.tsv` 片段（四列：旧词/新词/mode/source）：

```
# compiled.tsv — batr glossary 产物，勿手编（patch 的唯一输入）
# profile=t2s  generated=2026-11-03 12:00:00
# sources: auto(exact 2600条 / sub 3200条) glossary/shared/name.tsv(exact, 2条) ...
白子＊TERROR	白子＊恐怖	exact	glossary/shared/name.tsv
奇普托斯	基沃托斯	sub	glossary/shared/text.tsv
學生會(?!變|陷|在|要|被)	學生聯合	re	glossary/local/text.tsv
```

命中日志片段（hits 降序、零命中沉底）：

```
# batr patch 词表命中日志（生成于 2026-11-03 12:34:56）
# 旧词	新词	mode	source	hits
奇普托斯	基沃托斯	sub	glossary/shared/text.tsv	4210
聖園彌香	圣园未花	exact	glossary/local/name.tsv	808
```

一个体现 re 上下文条件的完整链路：

- 正文 `學生會的活動` 不命中 exact；sub 桶里最长匹配不到整词，re 规则 `學生會(?!變|陷|在|要|被)` 否定前瞻通过，替换为 `学生组织的活動`。
- `學生會變強了` 因前瞻失败保持原样。
- 最后两者都经 OpenCC 转为简体——普通词表负责主体替换，re 只做兜底的上下文修正。
